# ADR 0019 - PostgreSQL server-side sessions with protected cookies

Current package approval: [Q98 approved v2](../../context/README.md#q98---whole-package-approval). Earlier pending/open statements below are historical interview evidence; current rules remain in their linked owners.

**Status:** accepted. **Decision:** D080. The Team Leader selected Q80 option A ("Tôi chọn A"), confirming the full proposed package. Authoritative policy is owned by [D080](../../context/design/architecture.md#d080---postgresql-server-side-sessions-with-protected-cookies).

Choose server-side PostgreSQL sessions and opaque protected-cookie tokens over JWT access/refresh tokens. This reuses the chosen database and supports the already-approved revocation/current-authority rules, accepting server-side session lookup on authenticated requests. Hash stored tokens, use protected cookies with a new token on login, deploy frontend/API under one HTTPS origin, and apply CSRF token/origin protections including login/logout. Allow concurrent sessions, current-session logout and all-session invalidation on existing access-change events. The Team Leader approved 30-minute idle and 8-hour absolute timeouts as project values, not externally mandated thresholds.

The security design was checked against [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) and [CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html). [D097](../../context/design/architecture.md#d097---pnpm-toolchain-development-quality-and-reference-operations) approves the argon2 password-hashing library and toolchain/library/environment baseline; D087 selects Caddy. No session library, deployment provider or new cache infrastructure is selected. Exact versions, pins, implementation and target-environment verification remain outstanding.

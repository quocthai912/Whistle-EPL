# BM-01 authentication measurement

- **Date** 2026-11-06 (Asia/Bangkok)
- **Task** T045 and SC-002
- **Measured server revision** [ee5da91](https://github.com/quocthai912/Whistle-EPL/commit/ee5da91b1b8b8fdece641ed6b6790f7df9280093)
- **Client** k6 1.6.1 (commit 2ac2bb560e), Windows amd64. The download SHA-256 matched the official release manifest.

## Profile and fixture

Node 24.14.0, PostgreSQL 17.11 and Caddy 2.11.7 ran together in an isolated
Linux container on Docker Desktop. The container's effective CPU set was
`0-3`, memory limit was 8,589,934,592 bytes (8 GiB) and swap limit was 0.
PostgreSQL used a dedicated volume on the SSD-backed Docker VM. The Windows
host reported a healthy NVMe SSD. The container saw 932 GiB available on
its data filesystem. The Windows k6 process ran outside the server cgroup.

Applied all seven committed migrations to the separate disposable
`whistle_test_bm01` database. Seeded 101 synthetic active accounts with unique
usernames, independently salted Argon2id hashes and completed-change state.
The first 100 identities each made one successful-workload attempt. The extra
identity was used for the negative run. The test reset is a fresh isolated
database and the same fixture shape. It does not operate on deployment data.

## Commands and measurement

Use [authentication.js](../../../tests/performance/authentication.js) with
k6 on PATH, a trusted HTTPS loopback origin in `BM01_ORIGIN`, explicit
`BM01_ISOLATED=ISOLATED_AUTH_FIXTURE` and `BM01_FIXTURE` pointing at an
untracked synthetic JSON file with `usernames` and `password`. Use
`bm01.fixture.000` through `bm01.fixture.100` for those fixture usernames.
Run `pnpm test:load` for the baseline and rerun with `BM01_MODE=negative`
for the throttling probe. The local test used `https://localhost:8452` and
normal certificate validation. The temporary Caddy root was removed afterward.

The 20 virtual users each ran five iterations. Each iteration acquired a real
prelogin cookie/CSRF context and submitted an HTTPS login. The login latency
includes the login request/response. The iteration measurement also includes
prelogin setup. Exact Origin, request protection, throttling, Argon2id and
session/audit transactions stayed active. The baseline counts only successful
logins that return full session eligibility toward the three-second threshold.

Independent database counts were 101 accounts, 100 sessions, 100 successful
login audit records and five persisted login failures.

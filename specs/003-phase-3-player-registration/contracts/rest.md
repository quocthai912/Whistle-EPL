# PHASE 3 REST Contract

Use the approved [UC08–UC11 route map](../../../context/use-cases/registration.md#derived-rest-and-dto-contract-map) and D085/D096. Routes below are relative to /api/v1. Commands are allowlisted. Bind UUID resource IDs, expected revisions and exact submitted version IDs where applicable. Use approved page/filter/sort and status/envelope conventions. Existing session and CSRF headers apply. File bytes follow [media](media.md).

| Operation | Request and result | Key constraints |
| --- | --- | --- |
| GET/POST /seasons/{seasonId}/club-applications | Scoped filters/page or draft creation with Club and draft fields. Return case/version, workflow status and permitted history. | Season authority, unique club-season case, selected owner IDs. |
| PATCH /club-applications/{caseId}/draft | Expected revision and allowlisted BM1 draft fields. | Submitted content immutable. D059 completeness at submission milestone. |
| POST /club-applications/{caseId}/{action} | Explicit receive, submit, approve, return, reject, withdraw or cancel. Use exact version, revision and reason where required. | D053/D055 authority, timing and supplementation. |
| UC08 D053/D100 command family | Propose and decide the exact receipt exception or correction. D100 inputs include approved basis, permitted descriptive changes, reason and evidence. Return bounded version/decision facts. | Independent decision and separate receipt/correction gates. Preserve original receipt. |
| GET/POST /players; GET/PATCH /players/{playerId} | Scoped lookup/search or authorized profile maintenance with code, name, date, catalog keys, expected revision and correction basis where applicable. | D034/D036/D058/D059/D092. Duplicate review acknowledgment identifies the candidate basis. |
| POST /players/{playerId}/portrait and /portrait/remove | Validated upload or explicit removal with current reference/revision. | D069/D094. Return a permitted application media reference, never a storage location. |
| GET/POST /seasons/{seasonId}/player-registrations; PATCH /player-registrations/{caseId}/draft | Scoped list or authorized draft preparation. Bind Player, Club, shirt, evidence and playing dates where applicable. | Validate parent season, authority and milestones. |
| POST /player-registrations/{caseId}/{action} | Allowlisted intake, supplementation, cancellation, validation, confirm-valid, termination, transfer, plan change/cancel, D053 exception and D057 correction proposal, approval, return-for-supplementation and rejection actions. Exact related versions/revisions and reasons are required where applicable. | Validation is a read-only business check through UC10. Decisions use the [execution contract](execution.md). |

Use D092 approved normalization and format bounds, including explicit stable codes, birth date as a calendar date no later than the current Vietnam date, reference keys from the approved catalogs, and representative phone as a string up to 32 characters with 7–15 digits and the approved punctuation. Report criterion, finding and applicable rule basis for permitted UC11 feedback. Keep restricted evidence, internal notes and contact details out of public projections and unsafe errors. Apply the D096 error families for invalid input, missing access, stale revision/basis, temporary unavailability and oversized or unsupported media. Do not provide a generic status write or public eligibility service.

# PHASE 3 Portrait and Recovery Contract

Apply [D069/D094](../../../context/design/media.md), D087/D088/D089 and the approved [PHASE 2 media/recovery contract](../../002-phase-2-season-regulations/contracts/media-recovery.md). Verify its accepted interfaces at the execution gate. UC09 uses the existing selected local storage profile or approved configured Internet alternative.

- Validate actual static PNG/JPEG/WebP, size ≤2 MiB, each dimension ≤2048 and successful decode. Reject animation and unsupported formats. Normalize and store immutable bytes under a server-generated name. Participate in maintenance admission while staging and switching the reference.
- Recheck current Player management authority, revision and source reference at the switch. A storage or database failure preserves the old reference. Removal clears the reference and uses fallback. Record operator/time and before/after references.
- Serve current authorized images through the backend with correct Content-Type and no-store. Require current profile read authority or a known authorized public seasonal basis on each read. Use the current portrait in historical views, accessible fallback and aspect preservation. Use the accepted backend GET /media/{assetId} contract. Synchronize a read/reference-switch race on the owning Player so authorization and current-reference checks are linearized before byte delivery. Older files cannot be read from obsolete application references. Keep storage private.
- Coordinate daily cleanup, 24-hour grace from becoming unreferenced, current/in-flight references and retained backup sets under D094. For staged bytes left without a committed asset after rollback, record first inventory observation and wait at least 24 hours from that observation before eligible deletion. A failed cleanup cannot corrupt a current image and is retried under the approved job policy.
- Exercise matched metadata and content backup/restore on separate isolated targets. Verify set identity, completeness, selected profile, schema and checksums before replacement. Exercise interrupted restore between database and content, keep maintenance closed until the same set is verified, and require fresh login after release. Verify current reference, fallback, retained-set protection and obsolete reference denial. PHASE 10 retains full-season BM-07 acceptance.
